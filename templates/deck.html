{# ======================= 3. PPM: overview ======================= #}
{{ head(3, "PPM · PRODUCT / PROJECT PLANNING & MANAGEMENT", "Vision, scope and stakeholders") }}

Product vision

Give an online store one place to run every return, from the customer's doorstep to a graded item and a correct refund, with every step on record.

Objectives

  • Enforce return rules automatically
  • Grade items A / B / C and route them
  • Compute refunds exactly, once
  • Live tracking for the customer

In scope

  • 6 roles, 13-status workflow
  • Pickup booking, 2 attempts
  • QC checklist, fraud check
  • Refurbish & re-inspection
  • Refund + inventory log
  • Admin dashboard & flags

Out of scope

  • Real payments / payment gateway
  • Passwords & real accounts
  • Courier API integration

Stakeholders

Customerreturns items, tracks refund
Pickup agentcollects parcels
Warehousechecks parcels in
QC inspectorgrades items
Refurbisherrepairs grade B
Adminmonitors, flags

{# ======================= 4. PPM: process & schedule ======================= #}
{{ head(4, "PPM · PROCESS MODEL & PLAN", "Incremental delivery in seven increments") }}

Each increment was built, tested with pytest, run, and committed to Git before the next one started. Definition of done: all tests green and the app runs.

    {% set inc = [ ("a", "Core", "Models, config, services, unit tests"), ("b", "Data", "Seed data through real services"), ("c", "Customer", "Orders, return, pickup, tracking"), ("d", "Operations", "Agent, warehouse, QC, refurbisher"), ("e", "Admin", "Dashboard, charts, flags"), ("f", "Experience", "Design system, 3D scenes, effects"), ("g", "Hardening", "Edge cases, docs, end-to-end demo")] %} {% for code, name, what in inc %}
  1. INC {{ code|upper }}{{ name }}{{ what }}
    2. {% endfor %}

Why incremental?

Business rules first, UI later: the riskiest logic (state machine, refunds) was tested before any screen existed.

Work breakdown

Data model → services → routes → templates → visual design → testing & docs.

Tools

Python, Flask, SQLite, pytest, Git, VS Code, Playwright for screenshot checks.

  autonumber
  actor QC as QC inspector

  participant DB as SQLite
  QC->>B: tick checklist, choose grade A, Stamp it
  B->>R: POST /qc/inspect/RL-2026-0004
  R->>W: submit_inspection(ret, checklist, "A")
  W->>SM: change_status(Received → Inspected)
  W->>SM: change_status(Inspected → Restocked)
  W->>F: issue_refund(ret, "Restocked")
  F->>F: calculate_refund(base, A, reason)
  F->>SM: change_status(Restocked → Refunded)
  F->>DB: INSERT refund, inventory_log, status_history (one COMMIT)
  R-->>B: 302 redirect to queue + toast
  Note over B,DB: Customer's tracking page polls GET /api/return/code/status every 5 s and moves the parcel
